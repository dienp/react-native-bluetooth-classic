# Spec Delta

## Purpose

Defines how the library integrates with React Native's new architecture. Covers registration, the delivery and shape of events, subscription semantics, logging, and the cleanup that runs when the JavaScript runtime goes away.

## ADDED Requirements

### Requirement: New-architecture native module
The library SHALL register a single TurboModule generated by React Native codegen from a typed spec. It SHALL work in bridgeless mode, SHALL NOT use legacy bridge APIs, and SHALL NOT require the legacy interop layer.

#### Scenario: Bridgeless Android app
- **WHEN** an Android app on React Native 0.82 or later runs in bridgeless mode
- **THEN** every API call and every event works as specified

#### Scenario: Bridgeless iOS app
- **WHEN** an iOS app on React Native 0.82 or later runs in bridgeless mode
- **THEN** every API call and every event works as specified

### Requirement: Typed event subscriptions
Each event SHALL have a typed subscribe function, for example `onAdapterStateChange(listener)`. It returns a subscription whose `remove()` is idempotent. A listener SHALL receive only events emitted after it subscribed, unless a spec says otherwise. Removing one listener SHALL NOT affect other listeners of the same event.

#### Scenario: Removing a subscription twice
- **WHEN** an app calls `remove()` twice on the same subscription
- **THEN** the second call has no effect, and other listeners keep receiving events

#### Scenario: Two listeners for one event
- **WHEN** two listeners subscribe to the same event and one of them is removed
- **THEN** the remaining listener still receives every later event

### Requirement: Event ordering and threading
Events from one source, such as one connection, discovery session or adapter, SHALL be delivered to JS listeners on the JS thread, in the order the native layer observed them. A listener that throws SHALL NOT stop delivery to other listeners or break the library.

#### Scenario: Connection events in order
- **WHEN** a connection receives data and then the remote side disconnects
- **THEN** listeners receive every data event before the connection's `disconnected` event

#### Scenario: Throwing listener
- **WHEN** one data listener throws an exception
- **THEN** other listeners of that connection still receive the same data, and the connection stays open

### Requirement: Event payload conventions
Every event payload SHALL be a plain, immutable object. Field names SHALL be the same on both platforms. Timestamps SHALL be numbers of milliseconds since the Unix epoch (UTC). Device objects in events SHALL have the same shape as those returned by the corresponding APIs. Fields that exist on only one platform SHALL be optional and documented.

#### Scenario: Timestamp format on Android and iOS
- **WHEN** an adapter, discovery, bond, accessory or connection event is delivered on Android or iOS
- **THEN** its `timestamp` is a finite number of milliseconds since the Unix epoch

#### Scenario: Device shape in events
- **WHEN** a device-found event is delivered on Android
- **THEN** its `device` has the same fields as the elements returned by `getBondedDevices()`

### Requirement: Events without listeners are harmless
The native layer SHALL emit events whether or not JS listeners exist. Emitting with no listeners SHALL produce no warnings, errors or crashes. Correctness SHALL NOT depend on counting native listeners.

#### Scenario: No listeners registered
- **WHEN** the adapter turns off while no listener is subscribed to adapter state
- **THEN** no warning or error is logged and nothing fails

### Requirement: Non-blocking native calls
No API call SHALL block the JS thread or other library calls while Bluetooth I/O is in progress. A slow write or connect on one connection SHALL NOT delay calls on other connections or calls to unrelated APIs.

#### Scenario: Slow device during a pending write
- **WHEN** a write to a slow device is still pending and the app calls `getConnections()` and writes to a second connection
- **THEN** both calls complete without waiting for the first write

### Requirement: Teardown on runtime invalidation
When the React Native runtime is reloaded or destroyed, the library SHALL tear everything down, so that nothing from the old runtime survives into a new one:
- close every connection and server socket
- stop discovery
- unregister every OS receiver and observer
- cancel pending native operations

#### Scenario: Reconnect after a JS reload on Android
- **WHEN** an Android app with an open connection reloads its JS bundle and then connects to the same device again
- **THEN** the new connection succeeds, and no thread or socket from the previous runtime remains

#### Scenario: Reconnect after a JS reload on iOS
- **WHEN** an iOS app with an open accessory session reloads its JS bundle and then connects to the same accessory and protocol again
- **THEN** the new session opens successfully, because the previous session was closed

### Requirement: No payload logging by default
The library SHALL NOT write transferred data, device names or addresses to system logs (logcat or the unified log) unless the app enables debug logging with `setLogLevel('debug')`. The default log level SHALL be `'warn'`.

#### Scenario: Default logging
- **WHEN** an app with default settings exchanges data with a device
- **THEN** no payload bytes or decoded text appear in the system logs

#### Scenario: Debug logging enabled
- **WHEN** an app calls `setLogLevel('debug')`
- **THEN** the library logs operation and connection lifecycle details, prefixed with the library name
